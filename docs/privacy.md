# Privacy

This is the full list of what Claude Session Monitor reads, keeps, changes, sends and starts. It's a contract: a new read is added here first.

Your sessions stay on your Mac. The server listens on `127.0.0.1` only and answers only requests addressed to its own host name.

**What it keeps,** in `~/.claude-session-monitor`:

- `events.jsonl`: one line per Claude Code event, written by the hook. Each line has the time, the event's name, the session ID, its folder, the path of its transcript, the ID of the Claude Code process, the permission mode, and a subagent's ID when the event is one of its own. For a tool, its name and a short detail, up to 160 characters: a description, a file name or path, a command, a search pattern, a URL, a web search query, a skill's name or a title. It also has the first 200 characters of each prompt; a notification's type and its first 200 characters; how a session started and why it ended; the steps of a session's plan, at most 20 of 90 characters each, with their status; the first question a session asks you, up to 160 characters; and its last recap, up to 300 characters, and question, up to 140, with the words of up to two answer buttons offered under that question, 40 characters each, and the name of the Claude app action a button stands for, such as `commit`. For a reminder a session sets itself, it has when it fires, how often and its ID, never what it will do. For a scheduled task a session sets up, it has the task's title and ID, never its description or instructions. Past 8 MB the server moves it to `events.1.jsonl`, replacing the one before, while it runs and when it starts. `events.pos.json` holds where the server stopped reading it: a byte offset, the file's inode number and the 64 bytes before the offset.
- `sessions.db`: one row per session with its title, latest prompt, folder and the app's folder for it, transcript path, model, process ID, status, how its last turn ended, its last recap or question, an API error's first 160 characters, a short note this app writes ("You stopped it", "Closed in the middle of a turn"), the archived flag, its scheduled task if it's a run of one, its pending reminders and the tasks it set up, what it waits on while it waits on you (the same words the window shows, and which agent asked), when it last got a message and the IDs of the sessions whose question it passes on (so a restart keeps a question in one place), and when it started and was last active.
- `sessions.db.bad`: only if `sessions.db` ever can't be opened. The server moves the broken file here, as it was, and starts a new one; you can delete it.
- `server.log`: what the server prints (when it started, how many sessions it found, a usage check that was skipped, and any error with its stack, which can name files), and the app's own lines, marked `app:`: the path and version of Bun, the server's process ID and version, why a server was restarted, and a blocked attempt to leave the local page. Past 8 MB at a server start, the server moves the old part to `server.1.log`.
- `usage.json`: your plan's weekly and 5-hour usage, as two percentages and when each resets, written by the status line. Nothing else from what Claude Code gives a status line is kept.
- `usage-history.jsonl`: the week's share used each time it changes, with the time and when the week resets, for the week's curve. Only those three numbers per line, and a little more than a week of them.
- `probe/` and `probe.exp`: the empty folder and the script for the 10-minute usage check.
- `hooks/`: the app's copy of the hook and the status line, when the app installed them.

It never stores whole conversations.

**What it keeps only in memory,** never on disk: an answer you gave on a card (a button's words, or the words you dictated and sent, up to 1,000 characters; when you sent it, and whether it was sent), until the session's next prompt or until the session moves on without it, and when each session's plugin last asked for one, for a minute. While you dictate, the words so far live only in the window, until you send them or cancel.

**The microphone,** only in the app and only while you dictate on a card: from when you press its mic until you stop, send or cancel, 60 seconds at most. macOS asks once for the microphone and for speech recognition. The speech is turned into words on your Mac, with macOS's on-device recognition and never over the network; the app asks for that and listens to nothing else. The sound is never saved or sent, and the words go nowhere until you send them to that session. When a dictation ends, the app's log notes how long it ran, how many audio buffers came, the loudest level, how many results and how many characters it heard, never the words. It starts in your Mac's language, English or Spanish, and you can change it in the menu bar menu, and the words that send a dictation in Settings; the app keeps both in its settings. If you give it your own sounds for the start and end of a dictation, it reads those two files and plays them, nothing more.

**What it reads and never writes:**

- The names of the transcript files in `~/.claude/projects`, to find a session's transcript.
- The end of each session's transcript, the last 256 KB: how its latest turn ended (the closing message, an interruption, an API error), the model of its last reply (used only for a session the Claude app has no file for, such as one in a terminal), and whether a shell command it moved to the background is still running: the command's ID, when it started and its short description, never the command itself. When the server first meets a session, the last 2 MB, for its plan's steps, its last recap or question, with the answer buttons under it, and the model of its last reply. For a workflow, the last 4 MB, for the run's name: the name given in the call, the file name of its script, or the name and description written in a script passed inline. It never opens the script file.
- Next to each transcript, its subagents' and workflows' files: each agent's description, phase, model and whether it runs in the background, from its `.meta.json`; the end of its transcript, for its context size, its last tool with a detail of up to 160 characters, and whether it finished; a run's journal, for which agents finished; and whether the run's result file exists, without reading it.
- The name of each session's process, once, to check it's Claude Code.
- When the app starts and another program already answers on its port: that program's process ID, its arguments and its folder, only to check it's this app's own server from an older version before stopping it. Nothing of it is kept, beyond the process ID and version in `server.log`.
- The Claude desktop app's session files in `~/Library/Application Support/Claude`. Each is read whole, again only when it changes, and only these fields are kept: the Claude Code session ID and the app's own, its title, the archived flag, model, effort level, whether ultracode is on, folder, when it was created and last active, which scheduled task it's a run of, which session a side session was started from, and the app's summary of the latest turn: which message it sums up, whether the turn is complete, and its one-line note of what the turn needs from you, up to 200 characters.
- The app's `scheduled-tasks.json` in the same folder, for each task's ID, name, schedule, whether it's on, folder, the path of its file (for Reveal in Finder, never opened), when it was created and last ran, and when the app skipped a run and why, up to 40 characters. It never reads what a task does.

**What it changes:** the hook entries in `~/.claude/settings.json`, and its `statusLine` when you had none, and nothing else.

**What it sends:** once a day, and when you choose Check for Updates…, a request to GitHub's public API for the newest release of this app. It carries nothing about you or your sessions. GitHub sees your IP address, as with any web page. Turn the daily check off in Settings › Updates.

**The plugin** (`session-monitor`), when you install it, runs inside each session and does two things. It writes `usage.json`: the same two percentages and resets as the status line, when Claude Code measures them, and only if the app's folder exists. And in the background it asks the app's server, at `127.0.0.1` only, whether you sent an answer for that session; the request carries only the session's ID. When you did, it submits that answer as the session's next prompt. The server hands it only the words of a button that session offered, or the words you dictated and sent from that session's card (one line, up to 1,000 characters), only after your click. It reads nothing else, keeps nothing else and sends nothing anywhere else. Its answers part stays off in the app's own usage check, which the app starts with `CSM_PROBE=1`.

**What it starts:** every 10 minutes at most, while the hook is active, you have used Claude Code since the last check and the numbers are more than a few minutes old, Claude Code itself, for a few seconds, to read your usage (see the [guide](guide.md#weekly-usage)). Claude Code connects to Anthropic as it always does when it starts, with your own sign-in, and keeps its own record of the folder as it does for any folder you open; the app adds nothing to that and sends nothing of its own. If the folder isn't allowed yet, it tries again six hours later.
